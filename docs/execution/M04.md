## Pre-made decisions

- **D04.1 — merge module = `crates/liminal-source/src/merge.rs`** (AM-4.3),
  sibling of `paragraph.rs`: merging is a property of source blocks, not policy.
- **D04.2 — block alignment is identity-stable:** blocks pair across versions by
  `{#id}` when present on both sides; anonymous blocks pair by index among the
  anonymous blocks in order; base blocks absent on one side are deletions; new
  blocks are insertions at their position.
- **D04.3 — same-block dual edits are never auto-safe:** a deterministic
  line-level merge inside one block yields `UniqueOverlap` — a unique candidate
  that the safety predicate REFUSES (R4 §6: determinism is not safety). This is
  the `unsafe_unique_merge` scenario by construction.
- **D04.4 — graph-before-file ordering is unexecutable under ILRP:** `Graph(_)`
  steps execute inside the Finalize transaction in topo order; a plan where any
  file/external step depends on a graph step is refused by `IlrpDriver::run` with
  `IlrpError::Executor("graph-before-file ordering cannot be executed under ILRP")`.
- **D04.5 — heuristic-founded DAG plans carry `inverse: None`:** R4 §6 requires an
  inverse only for AUTOMATICALLY accepted repairs; the DAG plan auto-refuses on
  identity grounds, and human acceptance records `HumanApproval` evidence without
  a revert promise.
- **D04.6 — new aux namespaces** (`store::ns`): `JUR_PLAN = "jur.plan"` (persisted
  proposals, key `repair:<uuid>`), `JUR_DECISION = "jur.decision"` (the
  `RepairDecision` for each plan), `JUR_REPAIR = "jur.repair"` (accepted
  `RepairRecord`s, written in the Finalize txn).
- **D04.7 — `selected_rule` strings (exact):** `"save-promotion"`,
  `"disjoint-merge"`, `"id-insert-then-reattach"`, `"undo:<original repair id>"`.
- **D04.8 — `lim repairs` prints no timestamps** — UUIDv7 already orders records;
  clock output would break goldens.

## Data schemas

`merge.rs`:

```rust
pub enum MergeOutcome {
    /// No aligned slot changed by both sides (or identical changes): merged
    /// result is unique AND structurally disjoint.
    Disjoint { merged: String },
    /// A unique candidate exists but ≥1 slot was changed by both sides
    /// (line-disjoint within the block): deterministic, NOT safe (R4 §6).
    UniqueOverlap { merged: String, overlapping: Vec<String /* slot keys */> },
    /// No unique candidate (same lines touched incompatibly).
    Conflict,
}
pub fn three_way(base: &str, ours: &str, theirs: &str) -> MergeOutcome
```

Slot key = the block's `{#id}` when present, else `anon:<index>`.

Algorithm: parse all three with `paragraph::parse`; align per D04.2; per slot
compute `ours_changed`/`theirs_changed` vs base; no slot with both → `Disjoint`
(merged = per-slot changed side, deletions honored, insertions appended in side
order ours-then-theirs); slots with both but identical text → still `Disjoint`;
slots with both where the changed LINE sets within the block are disjoint →
line-level merge, `UniqueOverlap` listing those slot keys; otherwise `Conflict`.

`RepairRecord` persisted value = the six R4 §6 fields verbatim (serde of the
frozen struct), key `repair:<uuid>` in `JUR_REPAIR`.

New fixture (this order authors it): `fixtures/scenarios/dag_accept.scenario.toml`
— the `dag_id_then_reattach` world plus a final `accept_repair` step (AM-4.2) and
`[expect] terminal = "Committed"`; used by `crash_matrix_two_step_dag` and the
DAG-ordering trace assertions, because the base DAG fixture intentionally ends at
`NeedsReview`.

## Algorithms

### A. Plan builders

**Save-as-Promotion** (replaces M02's placeholder construction): single
`WriteFile` step; `expected_prestate` = observed base file hash (or `FileAbsent`);
`expected_poststate` = merged-bytes hash; `inverse` =
`Some(InverseRepairPlan(plan with one WriteFile of the OLD bytes, prestate = the
new hash, poststate = the old hash))`; subject = the FILE node (real, from M03
ingestion). Basis = `ClientScoped` capture (still M02-shaped until M6 makes
capture real — comment the seam).

**Foreign-edit ingestion + the two-step DAG** (`ingest::foreign_change` in the
daemon): on a foreign file change, re-parse; if a comment Relation's target alias
vanished and only a heuristic candidate exists (structural match), build:

```text
s_insert:   InsertSourceId { path, at: end-of-candidate-block, entity: E }
            prestate = FileContent(current hash); poststate = FileContent(hash after marker insertion)
s_reattach: Graph(RetargetRelation { id: r, target: Node(candidate) })
            prestate = RelationAt { relation: r, revision: current }
            poststate = RelationAt { relation: r, revision: current + 1 }
dependencies = [ { before: s_insert, after: s_reattach } ]
inverse = None                                   // D04.5
```

Finalize graph ops on acceptance: `RetargetRelation` + `DeleteNode(old node)` +
aux `JUR_ALIAS[alias] = {node: candidate, entity: E}` (EntityId continuity) +
`JUR_REPAIR[record]`, and the M5 order adds overlay-key deletion here.

**`InsertSourceId` execution** (`FsExecutor`, which gains a store handle —
AM-4.1's second half: `FsExecutor<'s> { root, store: &'s GraphStore }`):

1. `bytes = read(abs)`; hash must equal the step prestate (else the verify path
   already classified `Neither`).
2. `alias` = scan `JUR_ALIAS` for the entry whose `.entity == m.entity` → `a`.
3. `new_bytes = bytes[..at.start] ++ " {#a}" ++ bytes[at.start..]` (`at` was
   computed against prestate bytes at plan time; the hash check makes it valid).
4. `stage` + `commit_if(Some(prestate hash))`.
5. Ack with the observed poststate hash.

### B. `Checker::evaluate_repair` — the full v4 §7.7 conjunction (replaces M03's skeleton)

```
0. reasons = []
1. ONE VALID RESULT AT THE CAPTURED BASIS
   a. topo_order(plan) — Err(e) → "not a dependency DAG: {e}"
   b. per-step prestate vs basis: expected_prestate must match the basis component
      for its subject key, OR match an earlier (topo) step's expected_poststate on
      the same key (intra-plan chaining). Mismatch → "prestate mismatch for
      {subject}: {detail}"
   c. WriteFile merge steps: recompute three_way(base, ours, theirs) from
      SYS_BLOB + the current file; Conflict → "no unique result at the captured basis"
2. PER-SUBJECT AUTHORIZATION (mutation-local, Law 3F)
   a. authorize(plan) — each refusal → "unauthorized: {message}"
   b. any subject with repair_authorization == ReviewRequired →
      "{subject}: repairs to this item always require review"
3. IDENTITY + INVARIANTS (what stops the DAG — v4 §7.7 worked example)
   a. per InsertSourceId step: claim grade := Explicit if the target block ALREADY
      carries alias(entity), else Inferred (the binding was heuristically derived —
      nothing in Holder-controlled source proves it)
   b. per RetargetRelation step: req = relation.requires.minimum; effective grade
      of the new target = min(claim grades of plan steps establishing that
      target's identity; else grade_of(target)). !satisfies(req) →
      "reattachment relies on a heuristic match (inferred) but the relation
      requires {req}"
   c. dangling: no step may leave a PreserveAndSurface relation dangling
4. DOMAIN SAFETY (profile predicate — AM-4.1)
   group steps by governing profile; call profile.safety_check(plan, store);
   Err(rs) → reasons += rs. Evidence combination: all StructurallyDisjoint → one,
   descriptions "; "-joined; mixed kinds → "mixed safety evidence; automatic
   composition is not attempted in Phase -1"
5. IDEMPOTENT + REVERTIBLE
   every step has an idempotency_key (structural); revertible :=
   plan.inverse.is_some() OR every WriteFile prestate blob exists in SYS_BLOB;
   neither → "no revert path recorded"
6. reasons empty → AutoApply { evidence } ; else NeedsReview { reasons: sorted, deduped }
```

`ExternalFileProfile::safety_check(plan, store)`: per governed WriteFile step,
recompute the merge from `SYS_BLOB[base]`, `SYS_BLOB[ours]`, and the hash-verified
on-disk file (drift → `ReviewReason("the file changed while planning")`);
`Disjoint` with `merged == contents` → evidence; `UniqueOverlap{overlapping}` →
`"not structurally disjoint: both edits touch {keys}"`. `InsertSourceId` steps are
content-preserving (marker only) → contribute
`"id-insert: #<alias> content-preserving"` to the description.
`GraphNativeProfile::safety_check`: recomputes condition 3b for its steps; pass →
`DomainValidator { validator: "graph-native/identity-requirement", report:
"targets satisfy declared identity requirements at basis" }`.

### C. `ClientSession::save` (ends in the ONE IlrpDriver — R4 §4)

```
1. (path, base_hash, ours) = workspace buffer state          // M6 migrates this into AvailableInputs
2. persist SYS_BLOB[blake3(ours)]; base blob already persisted at open
3. if !holder_available(store, path) → M5 branch (stub: always available at M4)
4. outcome = three_way(blob[base], ours, current file bytes)
   Disjoint | UniqueOverlap → plan = save-promotion builder (merged bytes)
   Conflict → persist JUR_PLAN[draft plan carrying ours] + (M5: Overlay + item);
              return Ok(plan.id)                              // capture never rejected (Law 3B)
5. one txn: JUR_PLAN[plan] + JUR_DECISION[checker.evaluate_repair(&plan)]
6. AutoApply{evidence} → driver.prepare(plan, evidence); driver.run → expect
   Committed; return Ok(plan.id)
7. NeedsReview{reasons} → (M5 adds Overlay + reconciliation item in this txn);
   return Ok(plan.id)
```

### D. `plan_undo` + `lim repair undo`

```
plan_undo(record, current):
1. inverse = record.inverse.as_ref().ok_or(UndoBlocked::NoInverse)?
2. per inverse step: check expected_prestate against `current`:
   FileContent{path,hash} → current.components[Path(path)] must carry that hash;
   graph predicates and Any pass here (ILRP re-verifies at apply).
   mismatch → Err(StaleState{ detail: "<path>: expected <hex8>, found <hex8>" })
3. all match → Ok(inverse.clone() with basis := current.clone())
   (step/plan ids REUSED so a double-undo is detected as already applied)
```

CLI flow: unknown id → stderr + exit 1. `Ok(plan)` → evidence =
`StructurallyDisjoint{"undo of <id>: restores recorded preimages"}`;
`evaluate_repair` must return AutoApply; prepare + run; new record with
`selected_rule = "undo:<id>"`; stdout exactly `undone: repair:<uuid>\n`, exit 0.
`Err(StaleState{detail})` → build a reviewable proposal (preimage WriteFile steps
with prestate = the CURRENTLY OBSERVED durable hash — explicitly acknowledging it
would overwrite intervening edits, which is exactly why it needs review); persist
`JUR_PLAN` + `JUR_DECISION(NeedsReview)`; stdout
`undo queued for review: repair:<uuid> (<detail>)\n`, exit 0. `Err(NoInverse)` →
stderr `repair:<uuid> recorded no inverse`, exit 1.

### E. `lim repairs` output (zero records + zero nonterminal intents → zero bytes, exit 0)

```
repair:<uuid>  <selected_rule>  <evidence-kind>  <n> steps  undo available|undone|no inverse
repair:<uuid>  needs review: <first ReviewReason>            (JUR_DECISION without a record)
repair:<uuid>  interrupted (<state kebab>) — run recovery    (nonterminal ilrp.intent)
```

Sorted by repair id (UUIDv7 ⇒ chronological). `undone` = another record's
`selected_rule` is `undo:<this id>`.

## Discovered gaps

- **DG-4.1 — RESOLVED (reading (a), extended).** AM-4.1 gives
  `safety_check(&self, plan, &GraphStore)` which cannot read the on-disk file
  Algorithm B references. Resolution: structural disjointness is decidable from
  `(base, current, merged)` alone via the new `merge::overlap_slots(base,
  current, merged)` — a slot overlaps iff `current != base` AND `merged !=
  current` there; "ours" is not needed. Save plans persist the base blob to
  `SYS_BLOB[hash]` and carry it in a `BasisComponent::ObjectContent` component
  (the `Path` component holds the *current* durable hash, which §1b + ILRP
  validate). No disk read, no further signature change. Implemented + tested
  (`overlap_slots_*` in merge.rs).

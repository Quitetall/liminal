**Status:** proposed work order — unratified — 1.5 weeks. Authored at the M17

## Scope

Implement the Phase 1 deterministic formatter over the M18 lossless CST, expose
`lim fmt` and `lim expand`, and extend the existing `lim check` path to the Phase
1 source pipeline. This order does not add a grammar, graph semantics, HTML
backend, persistent daemon, transform runtime, or compiled Jurisdiction plan
(`docs/implementation-plan.md` §4 items 1, 4, 9, 12).

## Frozen surfaces

The existing `liminal_format::Formatter` seam, the exact test name
`formatter_idempotence_law_holds`, the M18 lossless-byte contract, the M19 stable
debug-JSON schema, and CLI spellings `lim fmt`, `lim check`, and `lim expand` are
frozen. Sound `lim check` remains exit 0 with byte-empty stdout and stderr.
`lim expand` emits only M19's canonical stable debug JSON. No new test function,
retry, or alternative formatter entry point may be added without amendment.

## Pre-made decisions

- **D20.0 (AM-17.3) —** `lim fmt` MUST format through
  `Formatter::emit_in_dialect` with the source's own dialect, never through
  `emit`. Formatting a compact Markdown document must return compact Markdown;
  rewriting it to `#!liminal-explicit-v1` on save would destroy the surface the
  reader chose.

- **D20.1 —** formatting is `parse → canonical emit`; it normalizes spelling and
  whitespace but never changes the M19 semantic graph.
- **D20.2 —** one formatter implementation serves the library and all three CLI
  paths; CLI code may not reimplement parsing, canonicalization, or diagnostics.
- **D20.3 —** `lim fmt` formats every governed external-file Holder selected by
  the explicit workspace root, in normalized path order, using per-file atomic
  replacement only when bytes differ. It preflights every selected Holder before
  the first write; once replacement begins, each completed file is durable and
  later write failure is reported as a partial failure with exact file
  coordinates, not hidden behind a false workspace-transaction claim.
- **D20.4 —** `lim check` performs parse, source-map, derived-graph, and formatter
  checks without writing; success is byte-silent and failures use deterministic
  path/range/code ordering with domain-native vocabulary.
- **D20.5 —** `lim expand` never writes source and prints exactly one canonical
  M19 debug-JSON document plus one trailing newline.
- **D20.6 —** malformed/opaque CST regions are preserved byte-for-byte. A region
  the formatter cannot safely canonicalize is emitted unchanged with a check
  diagnostic; it is never guessed or dropped.
- **D20.7 —** all positive, negative, malformed, and replay assertions are folded
  into the existing named gate so the declared test inventory does not change.

## Data schemas

No new persisted schema. The command contract is exactly:

```text
lim --workspace <root> fmt
lim --workspace <root> check
lim --workspace <root> expand
```

`fmt` writes only changed governed source files and otherwise emits zero bytes.
`check` never writes. `expand` writes canonical ADR-0016/M19 JSON to stdout and
nothing to stderr on success. Source diagnostics are sorted tuples
`(workspace_relative_path, start_byte, end_byte, code, message)`; byte offsets
refer to the exact Holder bytes at the selected Basis.

## Algorithms

1. Enumerate governed external-file Holders, reject non-concrete or ambiguous
   Holders, normalize paths, and process them in bytewise path order.
2. Parse through M18. Canonically emit supported CST nodes; copy opaque and
   malformed regions verbatim. Reparse emitted bytes and compare the M19
   canonical graph with the pre-format graph.
3. Run the formatter twice. Freeze `F20_IDEMPOTENT = second_bytes == first_bytes`
   and `F20_SEMANTIC = graph_before == graph_after` in
   `formatter_idempotence_law_holds` over valid, malformed, and already-formatted
   fixtures.
4. For `fmt`, stage all changed bytes first and perform no write unless every
   file passes Algorithm 3. Replace changed files one at a time with fsync-backed
   atomic replacement in normalized path order. If a write fails after replacement
   begins, preserve already completed files, stop, and report the exact partial
   failure coordinates for rerun/recovery.
5. For `check`, run the same parse and comparison without emission side effects.
   For `expand`, serialize the M19 graph with its canonicalizer and append one
   newline.

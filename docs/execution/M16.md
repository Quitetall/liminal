## Pre-made decisions

- **D16.1 —** development, locked acceptance, and regression corpora remain
  separate. A failure is minimized into regression data without exposing or
  altering locked source traces.
- **D16.2 —** any v2 corpus is independently sourced, sanitized, labeled, and
  locked by a custodian before profile authors receive only verifier results.
- **D16.3 —** v1 scores remain forever; a new version adds evidence and never
  overwrites history.
- **D16.4 —** Phase 0 security scope covers graph store, filesystem Holders,
  clients/buffers, resolver observations, repair execution, plugins/processes,
  corpus handling, and supply chain. Each boundary names assets, attacker,
  entry points, failure mode, control, detection, recovery, and residual risk.
- **D16.5 —** prior-art decisions adopt boundaries, not wholesale systems. Each
  v4 §118A reference gets Adopt/Adapt/Defer/Reject disposition with evidence and
  a falsifier.
- **D16.6 —** M13–M16 introduce no new stable profile or trace category, so v1 is
  reverified unchanged and v2 is not created. Discovery of a missing category is
  a T1 gap requiring a separately authorized custodian ceremony.

## Data schemas

`docs/security/threat-model.md` has one table row per threat:

```text
TM-ID | asset | trust boundary | attacker/capability | entry point |
failure mode | preventive control | detective control | recovery |
verification | residual risk | owner
```

IDs are `TM-<two digits>` and never reused. Severity uses a separate
`impact: low|medium|high|critical` and `likelihood: unlikely|possible|likely`
pair; no opaque combined score.

`conformance/fixtures/README.md` documents each fixture family, version field,
parser, canonicalizer, malformed-case policy, golden owner, and confidentiality
class (`public|sanitized|locked`).

## Algorithms

1. Build fixture inventory only from tracked paths outside locked corpus trees;
   verify each documented public/sanitized fixture family has a parser and owner.
2. Invoke existing locked-manifest and scorecard tests as black-box verifiers.
   Record exit status and committed scorecard hash; never print trace data.
3. Combine sound-session assertions in one gate: byte-empty diagnostics/checker
   output, zero unexpected items, zero manual Contract authoring, and no hidden
   transient debt past policy window.
4. Threat-model review uses abuse cases, STRIDE-style prompts only as coverage
   aids, and explicit crash/recovery verification. Unsupported mitigations are
   follow-ups, not claims.
5. Record one accepted ADR for the §118A disposition matrix after user review;
   any direct dependency adoption needing its own reversible decision gets its
   own ADR.

# M21 — Basis-explicit Salsa incremental compiler (v4 §§24, 112, 122, 125; Part XXII Phase 1)

**Status:** proposed work order — unratified — 2 weeks. Authored at the M17
Phase 0 gate. The executor implements mechanically only after explicit Phase 1
suite ratification; deviation = amendment or discovered gap, never silent.

## Scope

Implement Phase 1 full and incremental compilation behind Liminal-owned query
interfaces using Salsa 0.28.0 with default features disabled. Make source and
Workspace Basis inputs explicit and prove incremental output equals an
independently executed full compile. This order does not perform effects inside
queries, build a daemon, persist a query database, add concurrency, or compile
Jurisdiction plans (`docs/implementation-plan.md` §4 items 4, 5, 7, 9).

## Spec inputs

v4 §§7.5, 8.6, 24, 110, 112, 122, 125, Part XXII Phase 1; R4 §§8, 10;
`docs/implementation-plan.md` §§3–4; ADR-0017, ADR-0018, ADR-0020; M18 lossless
CST, M19 derived graph, and M20 formatter/CLI outputs.

## Frozen surfaces

Dependency version `salsa = 0.28.0` with `default-features = false`, the public

## Pre-made decisions

- **D21.1 —** add exact Salsa 0.28.0 to workspace dependencies with
  `default-features = false`; `liminal-query` is its only direct production
  consumer in this milestone.
- **D21.2 —** Salsa is a private execution mechanism behind Liminal-owned source,
  Basis, compiler, dependency, and diagnostic interfaces.
- **D21.3 —** source bytes/revision and every selected Workspace Basis component
  are explicit inputs. Current directory, clock, environment, filesystem reads,
  resolver calls, and mutable singleton state are forbidden query inputs.
- **D21.4 —** full and incremental paths may share published input/data schemas
  but not the incremental cache, changed-key set, or expected-output builder.
- **D21.5 —** output equality is byte-exact canonical M19 graph JSON plus ordered
  diagnostics and, after M22, deterministic HTML; pointer or Salsa-ID equality
  is never evidence.
- **D21.6 —** changing one Basis component invalidates only queries whose recorded
  `ComponentDeps` contain that key. Irrelevant-component mutations must leave
  results byte-identical and cached dependencies unchanged.
- **D21.7 —** all differential, stale-Basis, malformed, negative, and replay
  assertions live in the existing gate so the test inventory stays fixed.

## Data schemas

No persisted query schema. Liminal owns the in-memory boundary:

```text
FullCompileInput        = (source_bytes, source_revision, WorkspaceBasis)
IncrementalCompileInput = (source_bytes, source_revision, ordered_edits, WorkspaceBasis)
CompileOutput           = (canonical_graph_json, ordered_diagnostics, ComponentDeps)
```

`ordered_edits` are M18 byte edits in ascending `(start, old_end, new_end)` order
and must be non-overlapping. Diagnostics use M20's deterministic tuple. Salsa
keys and revisions never serialize or cross the `liminal-query` crate boundary.

## Algorithms

1. Add the pinned dependency at the workspace root and consume it privately from
   `liminal-query`; compile with default features disabled.
2. Build the full oracle from a fresh database populated only by the declared
   source and Basis inputs. Run M18 parse and M19 lowering without incremental
   state.
3. Build the incremental path from the same public input values, apply ordered
   edits, update only changed explicit inputs, and request the same Liminal-owned
   output query.
4. Compare canonical graph bytes, ordered diagnostics, and recorded Basis
   dependencies. Freeze `Q21_EQUAL = incremental == full` and
   `Q21_PRECISE = changed_keys ∩ deps == invalidated_keys` in
   `incremental_equals_full_compile_law_holds`.
5. Replay every case from a fresh database and randomized irrelevant Basis
   changes. A stale, missing, or ambiguous Basis fails closed; no query performs
   recovery or external resolution.

## Discovered gaps

against the Phase 0 `ParagraphCompiler`, which implements `incremental` as
`full(apply(x, edits))` and therefore satisfies the law by construction. The

milestone tests all pass without constraining anything.

M21 must re-examine every one of them when subtree reuse lands. A law that has
been green throughout is the easiest kind to assume is working, and this one has
never had the opportunity to fail.

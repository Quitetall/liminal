## Scope

Activate the Phase 1 production fuzz surface, retain every minimized failure as
a replayed regression, and turn the existing §116 Divan baselines into bounded
regression gates for the completed external-file source-to-HTML slice. This
milestone does not inspect or tune against locked acceptance data, invent a new
test, optimize past a measured regression, or activate snapshot migration before
the first persisted-format ADR (`docs/implementation-plan.md` §§4–5).

## Frozen surfaces

The existing test name `fuzz_regressions_stay_fixed` and its location in
`conformance/tests/classes/malformed_source.rs`; exactly five fuzz target names

  `format_idempotent`, `canonical_round_trip`, `incremental_full_equivalence`,

  projection, incremental compiler, and native renderer.
- **D23.2 —** each target starts with at least 16 declared, non-locked seeds and
  stores minimized failures under its own target directory. A failure is fixed
  only after its minimized input is committed and replayed by
  `fuzz_regressions_stay_fixed`.
- **D23.3 —** activate the existing Phase 1 charter entries `cold_startup` and
  `mem_per_node_and_relation`. The exact gated inventory is those two plus
  `store_append_txn`, `store_commit_fsync`, `store_recover_1k_records`,
  `relation_traversal`, and `graph_query_latency`. Each records exactly 30
  independent samples on the recorded reference environment. Candidate median
  and p95 values must be no more than 10% and 15% above baseline respectively;
  equality at either threshold passes. A missing or extra benchmark,
  environment mismatch, or missing raw sample fails closed.
- **D23.4 —** accepting or replacing a benchmark baseline is T1. A regression
  is investigated or separately approved; the executor never blesses the
  slower candidate merely to make the gate green.
- **D23.5 —** `old_snapshots_open_after_format_evolution` remains ignored. Only
  an accepted first persisted-format ADR activates its fixtures and flip; M23
  does not infer that decision from the presence of debug JSON.
- **D23.6 —** fuzzing and benchmarking use development/regression inputs only.
  Existing approved black-box verifiers remain the sole interface to locked
  acceptance inputs.

## Data schemas

`fuzz/targets.toml` contains exactly five `[[target]]` records, sorted by `name`:

```toml
[[target]]
name = "<D23.1 name>"
family = "<cst|format|projection|incremental|render>"
seed_dir = "fuzz/corpus/<name>"
regression_dir = "conformance/corpora/regression/phase1/<name>"
minimum_seed_count = 16
```

Each minimized regression is stored as
`conformance/corpora/regression/phase1/<target>/<sha256>.case` plus
`<sha256>.json`:

```json
{
  "schema_version": 1,
  "target": "<D23.1 name>",
  "input_sha256": "<64 lowercase hex>",
  "discovered_seed": "<recorded seed>",
  "reproducer": "<exact cargo fuzz command>"
}
```

`benches/baselines/phase1.json` is canonical UTF-8 JSON with benchmarks sorted
by `name`:

```json
{
  "schema_version": 1,
  "artifact_kind": "<baseline|candidate>",
  "subject_commit": "<40 lowercase hex>",
  "compared_baseline_commit": "<null for baseline; 40 lowercase hex for candidate>",
  "reference_environment": "<recorded environment identifier>",
  "toolchain": "<exact rustc version>",
  "sample_count": 30,
  "benchmarks": [
    {
      "name": "<fully qualified Divan benchmark name>",
      "unit": "<ns|bytes>",
      "samples": ["<30 JSON u64 values>"],
      "median": "<u64>",
      "p95": "<u64>"
    }
  ]
}
```

Baseline and candidate use the same schema; raw samples, not pre-rounded
percentages, are authoritative.

## Algorithms

1. Create one `cargo-fuzz` target for each D23.1 name. Every target treats
   panic, timeout, invalid memory behavior, nondeterminism, or disagreement with
   its independent/reference oracle as failure; it never filters an input after
   observing failure.
2. Seed each target with at least 16 declared valid, boundary, truncated,
   malformed, and hostile development/regression inputs. `just fuzz-smoke`
   executes every target with its committed seeds; the qualification run
   executes each target sanitizer-enabled for 31 minutes, exceeding ADR-0020's
   30-minute minimum without changing that minimum.
3. Minimize every failure, hash the exact minimized bytes, write the `.case` and
   metadata pair, then implement `fuzz_regressions_stay_fixed` as deterministic
   replay through the owning API. The test fails on a missing metadata pair,
   hash mismatch, panic, or reappearance of the recorded defect.
4. Run every implemented benchmark in the same recorded environment for exactly
   30 samples and sort ascending. Median is the truncating integer mean of
   samples 15 and 16 (one-based); nearest-rank p95 is sample 29. Avoid rounded
   percentages: require `candidate_median * 100 <= baseline_median * 110` and
   `candidate_p95 * 100 <= baseline_p95 * 115` with checked integer arithmetic
   for every benchmark.
5. `just bench-gate` emits the baseline/candidate value and both percentages for
   every benchmark, exits nonzero on any threshold or provenance mismatch, and
   never rewrites the accepted baseline. Baseline creation or replacement is a
   separate T1 step.
6. Leave the migration test ignored unless an accepted persisted-format ADR
   explicitly names the format and activation fixtures. Discovering such an ADR
   is an escalation to its owning work order, not an implicit M23 edit.

  failure is either absent or minimized into a replayed regression fixture.

  thresholds against a T1-accepted baseline.
- Migration remains ignored unless its accepted ADR trigger exists.
- `just ci` passes after the last fix with retries disabled.
- `just gates` matches the predicted unconditional counts; amendments and gaps
  are recorded before any deviation.

## Pre-made decisions

- **D05.1 — unavailability is store-resident, not filesystem tricks:** scenario
  step `holder_unavailable` writes `SYS_UNAVAILABLE[path] = {"mode":"read-only"}`
  (durable ⇒ survives the fixture's `daemon_restart`); `holder_available(store,
  path)` (M04's stub) reads it; the step `holder_available` deletes the key then
  runs `sweep_overlays`. `FsExecutor::apply` also consults it and returns
  `Executor("holder unavailable: <path>")` — defense in depth.
- **D05.2 — offline save still returns a `RepairId` with no API change:** the file
  is readable (read-only mode), so the plan IS built and persisted (`JUR_PLAN`);
  one txn writes plan + Overlay(`Active`, declared-transient lifecycle) +
  `SYS_BLOB[ours]` — **no** decision, **no** item (a profile-declared transient
  draft within its window ⇒ `reconciliation_items = 0`, `overlays = 1`, exactly
  the fixture, R4 §2.3).
- **D05.3 — coalescing keeps one current draft plus the full chain:** a second
  offline save to the same subject updates the existing `Active` overlay
  (`operation` = new draft, `last_activity` = now, same id/created_at) and appends
  `JUR_OVERLAY_LOG["overlay:<uuid>/0001"] = {"at":…, "operation":{…prior…}}`
  (4-digit seq) — v4 §7.10.2: coalesce without erasing history.
- **D05.4 — fake clock = store-resident offset, honestly traded:** REJECTED: a
  `LIMINAL_CLOCK` env read inside `Timestamp::now()` (core-crate amendment,
  per-call env) and a `Clock` abstraction (ripples through frozen structs).
  CHOSEN: `advance_clock { by_secs }` accumulates `SYS_CLOCK["offset_ms"]`; daemon
  helper `now_with_offset(store) = Timestamp::now() + offset` used by ALL aging
  math and by `lim overlays` (separate process, same store). `created_at` remains
  real wall time; determinism comes from offsets (days) ≫ test runtime (ms) plus
  coarse age rendering. This is a deliberate honesty trade, documented here; no
  core amendment.
- **D05.5 — root-cause key grammar (binding, reused by M11):**
  `<category>:<key>`, categories `conflict | identity | offline | ambiguity |
  undo` — e.g. `conflict:path:notes.md`, `identity:path:notes.md#p-fourier`,
  `offline:path:notes.md`, `undo:repair:<uuid>`,
  `ambiguity:client:<uuid>:path:notes.md`.
- **D05.6 — Overlay departure paths only:** accepted repair (the Finalize txn
  deletes the overlay key — history stays in the log), explicit discard, explicit
  searchable archive (v4 §7.10.7). No GC exists (prohibition #13).

## Data schemas

Overlay value (ns `JUR_OVERLAY`, key `overlay:<uuid>`):

```json
{"id":"<uuid>","subject":{"node":"<uuid>"},"base":{…WorkspaceBasis…},
 "operation":{"write-file":{"path":"notes.md","contents":[…]}},
 "created_at":1789000000000,"last_activity":1789000000000,
 "profile":"external-file",
 "lifecycle":{"surface_after":{"secs":3600,"nanos":0},"escalate_after":{"secs":86400,"nanos":0},"declared_transient":true},
 "state":"active"}
```

Creation sites (complete list): (1) offline save (D05.2); (2) NeedsReview save
(M04 Algorithm C step 7 — this order fills that seam: same txn writes one Overlay
with `state: RepairProposed(plan.id)` + one coalesced `conflict:` item);
(3) DAG proposal (two overlays — source-ID insertion + relation endpoint — one
item, per v4 §7.7); (4) ILRP recovery `Neither` → `Contested` (M02 machinery; M05
verifies the shape); (5) stale undo (M04 Algorithm D).

## Algorithms

### A. `ReconciliationQueue::upsert_coalesced`

1. Scan `RECONCILE_NS`; `existing` = first item with the same `root_cause` and
   status `Pending | Blocked`.
2. Existing → merged = existing with `subjects ∪=` (sorted, deduped),
   `overlays ∪=`, `repairs ∪=`, `status = item.status`; put under the EXISTING id.
3. None → put the new item.

### B. `sweep_overlays` (runs at workspace open after recovery, after every
scenario step, and before `lim overlays` / `lim check` output)

- Aging: per `Active` overlay, `age = now_with_offset − created_at`;
  `(declared_transient && age > escalate_after) || (!declared_transient && age >
  surface_after)` → upsert item (`offline:path:<p>`, Pending, overlays=[id]).
- Holder-return: overlay whose write route is now available → load/rebuild the
  plan (re-verify prestates; drift → rebuild via `three_way` at a fresh basis) →
  `evaluate_repair` → AutoApply ⇒ prepare + run (Finalize deletes the overlay key
  and resolves any covering item); NeedsReview ⇒ `state = RepairProposed(plan.id)`
  + item.

### C. `lim overlays` output (everyday vocabulary ONLY — R4 §3)

Zero active overlays → zero bytes, exit 0. One line per overlay, sorted by
`created_at` then id, two-space columns: `<status>  <path>  <age>`.

Status: `Active`+transient → `pending sync`; aged past escalate →
`pending sync (overdue)`; `Active` non-transient → `draft`; `RepairProposed` →
`review needed`; `Contested` → `review needed (conflict)`; `--all` adds
`archived`/`discarded` rows. Age: `<n>s` <60s, `<n>m` <60m, `<n>h` <24h, else
`<n>d`. Example: `pending sync  notes.md  5s`.

### D. `no_agenda_symbols` (mechanical enforcement of prohibition #4)

Test in `milestones/m05.rs`. Needle = the single token `agenda`,
case-insensitive, built at runtime by concatenation (`"ag".to_string() + "enda"`)
so the test's own source cannot match. Scan every `*.rs` under `crates/` and
`conformance/` (skip `target/`; `docs/` and `spec/` legitimately name the future
domain). Assert zero matches; print `file:line` on failure.

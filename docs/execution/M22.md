# M22 — Deterministic escaped HTML and incremental patches (v4 §§27, 110, 112; Part XXII Phase 1)

**Status:** proposed work order — unratified — 2 weeks. Authored at the M17
Phase 0 gate. The executor implements mechanically only after explicit Phase 1

## Scope

Create the native `backends/html` crate, render M19 Human IR to deterministic
escaped full HTML, and produce minimal block patches whose application is
byte-identical to a fresh render at the same Basis. This order does not add a
browser DOM runtime, JavaScript, CSS framework, Pandoc process, daemon preview
protocol, rich editor, or compiled Jurisdiction plan
(`docs/implementation-plan.md` §4 items 4, 6, 11, 12).

v4 §§9, 24, 27, 93, 110, 112, 125, Part XXII Phase 1; R4 §§2–3, 8;
`docs/implementation-plan.md` §§3–4; ADR-0015, ADR-0017, ADR-0018, ADR-0020;
M18 lossless CST, M19 Human IR/derived graph, M20 canonical formatter, and M21

## Frozen surfaces

Backend location `backends/html`, package name `liminal-html`, exact escaping
table, full-document framing, patch ordering and fields, M19 role mapping, and
test names `full_document_html_matches_golden` and
`incremental_patch_equals_full_render` are frozen. Pandoc and raw unescaped
source are forbidden on the native path. No new test function, nondeterministic
map iteration, retry, time-dependent byte, or hidden Basis lookup may appear.

## Pre-made decisions

- **D22.1 —** add `backends/*` to workspace members and create one publish-false
  Rust library crate `liminal-html`; it consumes Liminal-owned IR, never parser
  events or Salsa types.
- **D22.2 —** escape text and attribute values deterministically:
  `& → &amp;`, `< → &lt;`, `> → &gt;`, `" → &quot;`, and `' → &#39;`, in that
  recognition order so introduced ampersands are not escaped twice.
- **D22.3 —** unsupported or raw-HTML-like IR is an explicit render error. Source
  bytes are never inserted as trusted markup and no sanitizer is treated as an
  excuse for unsafe generation.
- **D22.4 —** full output is UTF-8 with prefix `<!doctype html>\n<html>\n<body>\n`,
  suffix `</body>\n</html>\n`, source-order blocks, deterministic attributes,
  and exactly one trailing newline.
- **D22.5 —** a patch replaces one stable M19 block at one explicit target Basis.
  Patches sort by new-document source order and contain already escaped complete
  replacement fragments.
- **D22.6 —** unchanged blocks emit no patch. Applying the ordered patch set to
  the old full document must equal a fresh full render byte-for-byte; otherwise
  patch generation fails closed.
- **D22.7 —** full goldens and patch/full equality are independent authorities:
  expected full HTML is reviewed fixture text, while patch tests compare against
  a separately invoked fresh renderer.

## Data schemas

No persisted backend format. The in-memory patch record is field-for-field:

```rust
pub struct HtmlPatch {
    pub basis: WorkspaceBasis,
    pub block: NodeId,
    pub replacement: String,
}
```

`replacement` is one complete escaped block fragment with its final newline.
The vector is sorted by the block's new-document source order; duplicate block
IDs, missing old targets, mixed Bases, or overlapping replacements are errors.
Full-render fixture pairs live under `conformance/fixtures/phase1/html/` and
reviewed snapshots under the existing `classes` integration-test snapshot path.

## Algorithms

1. Lower only published M19 Human-IR roles to a closed HTML tag mapping. Sort
   attributes by bytewise name, escape all text/attribute data with D22.2, and
   reject unknown roles or invalid structural nesting.
2. Render full output using D22.4 constants. Freeze exact bytes per fixture in
   the existing `full_document_html_matches_golden` snapshot gate; accepting or
   changing any golden is T1.
3. Given old and new M19 documents plus their explicit Bases, identify changed
   stable blocks from canonical IR equality, render only those blocks, and emit
   D22.5 patches in new source order.
4. Apply patches with an implementation independent from patch selection. Freeze
   `H22_PATCH_EQ = apply(render(old), patches) == render(new)` and the
   unchanged-block exclusion in `incremental_patch_equals_full_render`.
5. Exercise text containing every escape character, hostile tag/attribute text,
   malformed opaque source, reordered blocks, deletion/insertion, stale Basis,
   and deterministic replay inside the two existing gates.

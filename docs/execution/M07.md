## Pre-made decisions

- **D07.1 — placement:** lab code is a module of the conformance crate —
  `conformance/src/identity/{mod.rs, strategy.rs, ops.rs, gitenv.rs, matrix.rs,
  claims.rs}`. No new workspace member.
- **D07.2 — normalization** (shared by sidecar/content-hash/structural):
  `normalize(text)` = per line trim, collapse whitespace runs to one space, join
  `"\n"`, drop leading/trailing empty lines.
- **D07.3 — structural matching is defined, not vibes:** exact `normalize`
  equality first; else Jaccard over 3-gram character sets of normalized text
  (text < 3 chars = one gram); unique argmax ≥ 0.5 → `Recovered(score)`; tie
  (|Δ| ≤ 1e-9) → `Ambiguous`; best < 0.5 → `Lost`. A heuristic never grades above
  `Inferred`.
- **D07.4 — determinism:** every random choice comes from
  `SmallRng::seed_from_u64(seed)`; same seed twice → identical bytes (tested).
- **D07.5 — worst-outcome total ordering:** `Lost < Ambiguous < Recovered(c)`
  (lower c worse) `< Preserved(g)` (weaker grade worse, per
  `IdentityGrade::strength` — expose a helper if needed as an additive fn).
- **D07.6 — git version floor:** assert `git --version` ≥ 2.44 (merge-ort era);
  FAIL the run on older git — never skip; record the exact string in the report
  header.

## Algorithms

### A. The six strategies (observation → outcome, deterministic)

1. **inline-id** — re-parse after the op: id present exactly once →
   `Preserved(Explicit)`; ≥2 → `Ambiguous`; absent → `Lost`.
2. **sidecar** — per entry: unique block with equal hash at same index →
   `Preserved(Explicit)`; unique equal hash at different index →
   `Recovered(0.9)`; equal hash at ≥2 blocks → `Ambiguous`; no hash match →
   block at recorded index with Jaccard ≥ threshold → `Recovered(0.5)`; else
   `Lost`. Under `rename_move`, the sidecar moves with the file iff a seeded bool
   says so — both worlds exercised.
3. **content-hash** — blake3 of `normalize(text)`: equal hash exactly once →
   `Preserved(ContentAddressed)`; ≥2 → `Ambiguous`; zero (any text change) →
   `Lost`. (Version identity, not entity identity — the matrix is expected to
   show this.)
4. **structural** — D07.3.
5. **revision-anchor** — (1) bytes at `offset..offset+len` unchanged AND both
   contexts match → `Preserved(Anchored)`; (2) exactly one occurrence of
   `ctx_before ∥ anchored bytes ∥ ctx_after` anywhere → `Recovered(0.9)`;
   (3) exactly one occurrence of the anchored bytes alone → `Recovered(0.6)`;
   ≥2 occurrences at step 2/3 → `Ambiguous`; none → `Lost`.
6. **managed-graph** — the file mirrored into the M03 graph. Operations are
   tagged **observed** (driven as graph transactions: rename_move, split, merge,
   copy_paste, duplicate_identical, delete_recreate) or **foreign** (bytes changed
   behind the Holder: formatter_rewrite, external_edit, all git ops). Observed →
   assert entity continuity in the store → `Preserved(Managed)`. Foreign →
   re-ingest and fall back to rule 4 — honestly demonstrating v4 §19.2: Managed
   holds only while the Holder observes the operation.

### B. The eleven operations (exact seeded mutations)

1. `rename_move` — `git mv notes.md docs/renamed.md` (bytes identical).
2. `split` — seeded block with ≥2 sentences (split on `". "`); insert `\n\n` at a
   seeded sentence boundary; a `{#id}` marker stays with the seeded half.
3. `merge` — join two seeded adjacent blocks with one space; if both carry
   markers keep the first's, delete the second's.
4. `copy_paste` — append a byte-exact copy of a seeded block (marker included →
   duplicate id) after `\n\n`.
5. `duplicate_identical` — append TWO byte-identical copies of the anonymous
   block → three identical anonymous blocks.
6. `delete_recreate` — delete a seeded block; append a block with identical text
   but NO marker at the original position.
7. `formatter_rewrite` — deterministic: greedy re-wrap to width 72, collapse
   blank-line runs to one, strip trailing whitespace, single trailing newline.
8. `external_edit` — k = seeded 1..=3 blocks; per block one seeded mutation of
   {replace seeded word with `EDITED<seed>`, delete last sentence, prepend
   `Inserted by seed <seed>. `}.
9. `git_merge` — base commit; branch `b` edits block X; `main` edits block Y
   (X == Y with probability `overlap_probability`); `git merge -s ort --no-edit b`;
   conflicts per policy.
10. `git_rebase` — same divergence; `git rebase main` on `b`; `--continue`.
11. `git_cherry_pick` — commit on `b`; `git cherry-pick <sha>` onto `main`;
    `--continue`.

### C. Hermetic git runbook (`gitenv.rs`)

Env per case (nothing else inherited):

```
GIT_CONFIG_GLOBAL=/dev/null  GIT_CONFIG_SYSTEM=/dev/null  GIT_CONFIG_NOSYSTEM=1
HOME=<case tmpdir>  XDG_CONFIG_HOME=<case tmpdir>/xdg
GIT_AUTHOR_NAME=liminal-lab   GIT_AUTHOR_EMAIL=lab@liminal.invalid
GIT_COMMITTER_NAME=liminal-lab GIT_COMMITTER_EMAIL=lab@liminal.invalid
GIT_AUTHOR_DATE=2026-01-01T00:00:00Z  GIT_COMMITTER_DATE=2026-01-01T00:00:00Z
TZ=UTC  LC_ALL=C  GIT_TERMINAL_PROMPT=0  GIT_PAGER=cat  PAGER=cat
GIT_EDITOR=true  GIT_SEQUENCE_EDITOR=:
```

Script: `git -c init.defaultBranch=main init` → write template (+ sidecar when
active) → add/commit → `checkout -b b` → edits → commit → `checkout main` → edits
→ commit → run the op. Conflict policies (seeded choice): **ours** =
`git checkout --ours -- <file>`; **theirs** = `--theirs`; **union** = strip
conflict markers keeping both sides in order; then `git add` +
`merge|rebase|cherry-pick --continue`.

### D. Grading + matrix

Per (strategy, operation, seed): build base world, capture strategy state, run
op, observe per Algorithm A → one Outcome per tracked block; case outcome = worst
across tracked blocks (D07.5). Matrix cell = worst outcome across seeds.

### E. `claims_never_exceed_evidence` (`claims.rs`)

`cap(cell)`: `Preserved(g) → g`; `Recovered(_) → Inferred`;
`Ambiguous | Lost → Anchored`. `cap(column) = min over rows`; for `managed-graph`
compute over **observed** rows only (graph-native subjects have no file for git to
mangle — v4 §7.6).

Assertions:
1. `ExternalFileProfile.required_identity` (`Anchored`) ≤ `cap(col)` for each of
   inline-id, sidecar, structural, revision-anchor.
2. `GraphNativeProfile.required_identity` (`Managed`) ≤
   `cap(managed-graph | observed)`.
3. **grade_of ceiling:** for every inline-id cell where `cap(cell) < Explicit`
   (e.g. `copy_paste` → Ambiguous), replay that post-op file through the M03
   checker and assert a finding (JUR041/JUR042) is emitted — never silence.
   "No stronger claim than demonstrated" = every demonstrated degradation is
   either below the declared floor (1–2) or loudly surfaced (3).

Failure of 1–3 is the killer firing: demote the grade in the profile via ADR
before M08 begins.

## Discovered gaps

- **DG-7.1 (M07.7, assertion 3 aggregation).** Assertion 3's imperative — "for
  every inline-id cell where `cap(cell) < Explicit` … assert a finding
  (JUR041/JUR042) is emitted" — contradicts its own explanatory clause, which
  frames the guarantee as a *disjunction*: "every demonstrated degradation is
  either below the declared floor (1–2) OR loudly surfaced (3)." Taken literally,
  the imperative fails on inline-id **`Lost`** cells (a `{#id}` deleted with no
  duplicate — e.g. `delete_recreate`, `external_edit`'s last-sentence deletion, a
  git `ours`/`theirs` drop): the post-op file simply lacks that id, and a file
  that never carried the id is sound → the checker is byte-silent.

  **Candidate readings.** (a) Literal: every inline-id cell `< Explicit` must emit
  a finding → the killer fires on every `Lost` cell, demanding an ADR demotion the
  floors already encode. (b) Disjunctive (the explanatory clause): a degradation is
  honest iff it emits a finding **or** is bounded by the declared floor.

  **Resolution (reading b, spec-grounded in v4 §19.2).** §19.2 states that when
  external tools "delete … or recreate anonymous text, perfect logical identity is
  information-theoretically **unavailable**" — so a `Lost` id is *unsurfaceable by
  construction*, and the honest response is the Anchored floor, not a diagnostic.
  A duplicated id (`Ambiguous`), by contrast, *is* surfaceable (two blocks claim
  one id) and MUST never be silently accepted. Assertion 3 is therefore
  implemented as: for each inline-id cell with `cap(cell) < Explicit`, replay the
  post-op file through the M03 checker and assert **`Ambiguous ⇒ a JUR042 finding
  is emitted`**, while `Lost ⇒ cap(cell) == the ExternalFileProfile floor
  (Anchored)`, i.e. bounded by the declared floor (the "(1–2)" branch). This keeps
  the check non-vacuous (the `Ambiguous` branch has real teeth), never weakens the
  duplicate-collision guarantee, and matches the explanatory clause verbatim.
  Assertions 1–2 independently prove the floors are honest (they hold with
  equality: worst demonstrated cap == declared floor).

- **DG-7.2 (M07.3, structural exact-equality outcome).** D07.3 says "exact
  `normalize` equality first; else Jaccard … `Recovered(score)` … `Ambiguous` …
  `Lost`", but does not name the outcome of an exact match. Candidate readings:
  (a) `Preserved(Inferred)`; (b) `Recovered(1.0)`. **Resolution: (b).** The rule's
  listed outcome vocabulary for structural is `{Recovered, Ambiguous, Lost}` only
  — structural is a heuristic and never `Preserved` (v4 §19.2). "exact equality
  first" is the max-score fast path (Jaccard = 1.0). A unique exact match →
  `Recovered(1.00)`; ≥2 exact matches → `Ambiguous`. Both cap at `Inferred`, so
  no assertion outcome depends on the choice.

- **DG-7.3 (M07.4, B2 split has no valid target on the template).** B2 targets "a
  seeded block with ≥2 sentences (split on `". "`)", but every template block is a
  single sentence spanning two physical lines — `". "`-splitting finds no interior
  boundary. Candidate readings: (a) split is a no-op (no qualifying block); (b)
  split at interior line breaks. **Resolution: (b), the faithful generalization.**
  The split-boundary set for a block is the byte positions after each interior
  `". "` UNION the positions after each interior `"\n"`; B2 inserts a blank line
  (`"\n\n"`) at the seeded boundary from that set. The block's trailing `{#id}`
  marker rides with the *second* (later) half — the half that keeps the original
  last line — so inline-id sees the id exactly once (`Preserved(Explicit)`). A
  block with no interior boundary is not a split candidate; if no block qualifies
  the op is the identity (unchanged file).

- **DG-7.4 (M07.5, B9–B11 divergence edits under-specified).** The git runbook
  says "branch `b` edits block X; `main` edits block Y" but not the exact bytes.
  **Resolution (deterministic, seeded):** the edit replaces the block's FIRST word
  with a side-tagged token — `"BranchB"` on `b`, `"OnMain"` on `main`. X is a
  seeded block index; Y == X with probability `overlap_probability` (seeded),
  else a different seeded block. Overlap on the same block yields a real merge-ort
  conflict resolved per the seeded [`ConflictPolicy`]; disjoint blocks merge
  cleanly. This keeps the git cells a genuine function of merge-ort behavior while
  being byte-reproducible.

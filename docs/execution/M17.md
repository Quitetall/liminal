# M17 — Real-CST measurement and Phase 0 gate (v4 §§9, 119, 124; Part XXII Phase 0)

**Status:** work order — 2 weeks hard time-box plus gate review. Authored at the
M12 gate. The executor implements mechanically; deviation = amendment or
discovered gap, never silent.

## Scope

Re-measure annotated-source anchor recovery over a real CST substrate selected by
the accepted §119 grammar ADR, without promoting spike code to production. Run the
complete Phase 0 gate, author proposed Phase 1 work orders and test suite, and stop
for adversarial human ratification. This order does not begin Phase 1, claim Level
3 below its bar, or ratify the Phase 1 suite automatically.

## Spec inputs

v4 §§9, 19, 112–116, §§119, 121, 122, 124, 125, Part XXII Phase 0 and Phase 1;
R4 §§2, 8, 10, 11.6; accepted M15 ADRs; ADR-0020; M09 measurement machinery;
M13–M16; `docs/execution/template.md` and `docs/execution/phases.md` Phase 1.

## Frozen surfaces

Two-week spike time-box; M09 Level 2 remains the declared level unless the new
measurement clears every Level 3 condition; merge-class recovery bar is at least
95%; M09 goldens remain unchanged; Phase 0 test names and counts from M13–M16;
Phase 1 suite status is `proposed` until explicit user ratification. Locked corpus
trees are outside spike input and may be touched only by existing black-box tests.
ADR-0020's HAQP-1 thresholds are frozen minimums; equivalent-mutant dispositions,
tool failures, or campaign runtime cannot silently lower them (AM-17.1).

## Pre-made decisions

- **D17.1 —** real-CST experiment lives under `conformance/spikes/real-cst/` and
  may depend on a mature parser selected by the accepted grammar ADR. No
  `liminal-cst` production API is created here.
- **D17.2 —** use development/regression projection fixtures only. Train/test
  cases are declared before measurement; no case is removed after failure.
- **D17.3 —** Level 3 requires merge-class anchor recovery ≥95%, all supported
  canonical round-trip laws, selection/mark boundary survival, malformed-input
  non-panic behavior, undo correctness, and no undeclared loss. One failed
  conjunction keeps Level 2.
- **D17.4 —** report records numerator, denominator, Wilson 95% interval, failures
  by class, seeds, toolchain/dependency versions, git commit, and wall-clock time.
- **D17.5 —** Phase 0 GO is a new T1 decision after adversarial review. Green CI
  is necessary, never sufficient.
- **D17.6 —** Phase 1 work orders and tests are proposed at the gate. Ratification
  requires a separate user-directed adversarial review; no checkbox or passing
  test can substitute for that human decision.

```text
status: measured

```

Follow with a deterministic table: case ID, edit class, seed, expected anchor,
observed anchor, outcome, declared loss. Sort by `(edit_class, case_id, seed)`.
`git_commit` records the parent commit used to run the measurement;
`measurement_tree` records the staged source tree. `elapsed_ms` is evidence shown
in the report but redacted to `<MEASURED>` by golden comparison, matching M07's
provenance-redaction pattern.

`docs/execution/phase1-suite-review.md` records suite version, fixed review base,
test inventory, law/class/abuse/fault coverage matrices, mutation-testing results,
fuzz budgets, uncovered risks, reviewer findings with verification disposition,
and status `proposed|ratified|rejected`. It also records the ADR-0020 HAQP-1
profile, continuous- and qualification-lane commands, bidirectional requirement
mapping, mutant numerator/denominator and dispositions, gate-canary results, five
generated/fuzz family reports, oracle-independence audit, registered crash-boundary
inventory, dependency/toolchain provenance, raw artifact hashes, campaign elapsed
time, and residual-risk coordinates. Initial status is `proposed`.

## Algorithms

1. Freeze case inventory and seed set before running. Hash only the declared
   development/regression inventory, never locked acceptance data.
2. For each case, run parse → annotate → foreign edit → incremental reparse →
   anchor recovery plus full-reparse oracle. Compare canonical graph, exact loss,
   selection/mark boundaries, and undo. Catch panics as failures.
3. Compute merge rate and Wilson interval from integer counts. Assign Level 3 only
   when every D17.3 conjunct passes; otherwise preserve Level 2 and enumerate
   blockers. Accepting the golden is T1.
4. Run Phase 0 exit: M13–M16 tests, both stable-profile SLOs, all Phase -1 tests,
   `just ci`, and `just gates`. Freeze the clean review base before suite
   qualification; adversarial passes run only after the proposed suite exists.
5. Author Phase 1 work orders from `template.md`. Every Phase 1 law/class test has
   positive, negative, malformed/adversarial, basis/provenance, and deterministic
   replay coverage where applicable. Implement ADR-0020's two lanes and complete
   HAQP-1: exact traceability, at least 64 semantic mutants with 100% applicable
   kill rate, disposable gate canaries, 100,000 deterministic cases and a
   30-minute sanitizer-enabled fuzz campaign for each of five critical families,
   independent oracles, exhaustive registered crash boundaries, and two blinded
   adversarial passes using distinct reviewer identities and isolated session
   state. Pass 1 attacks vacuity, oracle independence, negative cases, crash
   completeness, and corpus leakage. Pass 2 starts from the original spec and
   attempts to falsify conclusions without seeing Pass 1's record. Record all
   gaps; do not weaken existing ignored tests.
6. Stop after proposed suite and review packet are complete. Notify user with exact
   commands, counts, artifacts, findings, and residual risks. Only explicit user
   ratification changes suite status and authorizes Phase 1 execution.

## Amendments

AM-17.1 (user-ratified 2026-07-20): require ADR-0020 HAQP-1 before the proposed
Phase 1 suite becomes eligible for ratification. This strengthens the existing
packet gate without adding or renaming tests; predicted counts remain unchanged.

AM-17.2 (user-ratified 2026-07-20): resolve the pre-authorization qualification
cycle with a Phase-0-only executable reference harness, synthetic subjects, and
five sanitizer fuzz targets. These qualify shared test contracts, not production
Phase 1 code; all seven Phase 1 gates and the conditional migration gate remain
deferred. Use five critical mutation families with thirteen predeclared semantic
mutants each, sixteen disposable canaries, and two concurrent blind reviewers:
DeepSeek V4 Pro plus a context-free Codex agent. A first clean HAQP run exceeding
eight hours is diagnostic and ineligible; optimize and rerun. A second clean
overrun requires a superseding ADR. No threshold is reduced.

## Discovered gaps

DG17.1 (M17.1): ADR-0015 selects the constrained Markdown-compatible frontend
but does not bind a concrete parser package. The spike pins
`tree-sitter-md 0.5.3` with `tree-sitter 0.26.3` because it exposes block and
inline CSTs plus edited-tree incremental reparsing. Upstream explicitly warns
that its Markdown output retains known inaccuracies, and it has no lossless
native serializer; M17 therefore treats it as measurement evidence only and
keeps the declaration at Level 2. No production `liminal-cst` API depends on it.

DG17.2 (M17.4): ADR-0020 requires five fuzz campaigns before Phase 1 suite
ratification, while the implementation-plan defer list originally created
`fuzz/` only after the production `liminal-cst` crate landed. AM-17.2 permits
only conformance reference targets before authorization and preserves the
production-parser prohibition.

## Exit criteria

- Real-CST report is reproducible, statistically explicit, and honestly graded.
- Every Phase 0 and retained Phase -1 gate is green; `just ci` and `just gates` pass.
- Two independent adversarial passes have zero unresolved verified findings.
- HAQP-1 qualification satisfies every ADR-0020 threshold from one fixed clean
  review base and the final full rerun.
- Proposed Phase 1 work orders and test coverage matrix are complete.
- User is notified; Phase 1 suite remains unratified until explicit acceptance.

# M17 — Real-CST measurement and Phase 0 gate (v4 §§9, 119, 124; Part XXII Phase 0)

**Status:** work order — 2 weeks hard time-box plus gate review. Authored at the
M12 gate. The executor implements mechanically; deviation = amendment or
discovered gap, never silent.

## Scope

Re-measure annotated-source anchor recovery over a real CST substrate selected by
the accepted §119 grammar ADR, without promoting spike code to production. Run the
complete Phase 0 gate, author proposed Phase 1 work orders and test suite, and stop
for adversarial human ratification. This order does not begin Phase 1, claim Level
3 below its bar, or ratify the Phase 1 suite automatically.

## Frozen surfaces

Two-week spike time-box; M09 Level 2 remains the declared level unless the new
measurement clears every Level 3 condition; merge-class recovery bar is at least
95%; M09 goldens remain unchanged; Phase 0 test names and counts from M13–M16;

- **D17.2 —** use development/regression projection fixtures only. Train/test

- **D17.3 —** Level 3 requires merge-class anchor recovery ≥95%, all supported

## Algorithms

1. Freeze case inventory and seed set before running. Hash only the declared
   development/regression inventory, never locked acceptance data.
2. For each case, run parse → annotate → foreign edit → incremental reparse →
   anchor recovery plus full-reparse oracle. Compare canonical graph, exact loss,
   selection/mark boundaries, and undo. Catch panics as failures.
3. Compute merge rate and Wilson interval from integer counts. Assign Level 3 only
   when every D17.3 conjunct passes; otherwise preserve Level 2 and enumerate
   blockers. Accepting the golden is T1.
4. Run Phase 0 exit: M13–M16 tests, both stable-profile SLOs, all Phase -1 tests,
   `just ci`, and `just gates`. Freeze the clean review base before suite
   qualification; adversarial passes run only after the proposed suite exists.
5. Author Phase 1 work orders from `template.md`. Every Phase 1 law/class test has
   positive, negative, malformed/adversarial, basis/provenance, and deterministic
   replay coverage where applicable. Implement ADR-0020's two lanes and complete
   HAQP-1: exact traceability, at least 64 semantic mutants with 100% applicable
   kill rate, disposable gate canaries, 100,000 deterministic cases and a
   30-minute sanitizer-enabled fuzz campaign for each of five critical families,
   independent oracles, exhaustive registered crash boundaries, and two blinded
   adversarial passes using distinct reviewer identities and isolated session
   state. Pass 1 attacks vacuity, oracle independence, negative cases, crash
   completeness, and corpus leakage. Pass 2 starts from the original spec and
   attempts to falsify conclusions without seeing Pass 1's record. Record all
   gaps; do not weaken existing ignored tests.
6. Stop after proposed suite and review packet are complete. Notify user with exact
   commands, counts, artifacts, findings, and residual risks. Only explicit user
   ratification changes suite status and authorizes Phase 1 execution.

AM-17.7 (user-ratified 2026-08-26): ADR-0020 §5's "exhaustive registered crash
boundaries" is scoped, for HAQP-1a, to the eight `ilrp/*` protocol boundaries.
Every other durable transition in the runtime is deferred to M17.9. The scope is
declared in `packet.crash_boundary_scope` rather than left implicit.

Rationale: §5 requires exhaustiveness without saying over what, and M17.5 A05
measured the honest answer. The registry covers **8 of the runtime's 38 durable
transitions**. `liminal-graph/src/store/mod.rs` documents its own commit path as
"Durable boundary: the record is fsynced before the commit returns", so every
`txn.commit()` is one — 22 in `liminal-daemon/src/runner.rs` alone — and none
carries a crash boundary. Registering them requires deciding which fsynced
transitions across the whole runtime are *registrable* boundaries, which is
runtime design work; doing it inside a qualification campaign would either block
1a on Phase 1 or settle the question by picking whichever definition passes.
ADR-0020 §3 forbids improvising qualification semantics, so the claim is bounded
and disclosed instead of quietly widened.

A prose scope note would rot the first time somebody added a commit site, which
is the same defect A05 found in the unscoped claim. `verify_crash_boundary_scope`
binds it to tracked source: every durable transition must sit inside a declared
in-scope subsystem or a declared deferred surface, with site counts matching
`git ls-files` exactly. A new `txn.commit()` anywhere turns the packet red until
it is registered or disclosed. Canary C33 pins the realistic failure — a surface
understated by one site.

Note for M17.9: A05's original survey claimed the daemon held 11 unregistered
crash-injection sites. It holds **zero** — `crash.rs` is the injector
implementation and `main.rs`'s `Fire` subcommand resolves its point from
`CrashPoint::all()`, so it is closed over the registry by construction. What
M17.9 inherits is the larger question the survey missed: which of the ~38
durable transitions are registrable boundaries.

AM-17.8 (user-ratified 2026-09-04): a registrable crash boundary is a point at
which a crash leaves state that recovery must reconcile. This is the criterion
AM-17.7 lacked. Under it ILRP's eight protocol steps are the boundary set, and
the runtime's remaining fsynced transitions — single checksummed appends whose
torn tail is truncated on recovery — carry no reconciliation obligation. The
evidence already existed: `prop_torn_tail_truncates_cleanly`
(`crates/liminal-graph/tests/store.rs`). A05 closes by definition plus citation,
not by registering thirty boundaries whose only test would be that an atomic
append is atomic. M17.9 no longer inherits it.

AM-17.9 (user-ratified 2026-09-07): how much rigour, and
where it is spent. Brian's governing sentence is *Liminal should not mess up in
real operation*, so qualification rigour is spent in proportion to how directly
a defect would reach a user's data, in this order:

1. **Durability and recovery.** A crash, kill or torn write must never lose or
   silently corrupt what the user was told is durable.
2. **Determinism and reproducibility.** The same inputs at the same Basis must
   produce the same result, or a revision cannot be replayed and the history
   the product sells is fiction.
3. **Faithful round-trip.** Nothing is accepted that cannot be re-emitted as
   its own meaning.
4. **Refusal over repair.** Input outside the domain is refused, never
   silently fixed.

Everything else ranks below these, and rigour spent below them is spent only
after they are satisfied.

The same sentence decides which blind-review finding blocks a flip:

- **Class A — suite blindness.** The finding shows the suite would not catch a
  real defect in one of the four ranks above. It BLOCKS. Unfixed, Liminal ships
  a behaviour nothing tests.
- **Class B — evidence untruth.** The finding shows the qualification record
  could assert something untrue about the suite or the tree, through drift,
  stale artifacts, or a digest that binds nothing. It BLOCKS. The packet is the
  artifact other work depends on, and a packet that lies is worse than no
  packet.
- **Class C — hostile qualifier.** The finding requires the party running the
  qualification to lie: forged receipts, edited records, arbitrary code as the
  runner. It is RECORDED and ruled, and does not block.

Class C does not block because **a gate cannot be its own adversary**.
Self-checking catches accident and drift, which is what has actually gone wrong
here — F-40's stale crash evidence, F-45's unverified report cells. It cannot
catch deliberate self-forgery: any check the runner performs, the runner can
skip. Only externally originated evidence narrows Class C, so the campaign
takes what is cheaply available — provider receipts (F-49), signed rulings
(F-48) — and states plainly that the remainder rests on a non-hostile
qualifier rather than pretending it is closed.

Termination follows: the loop ends when a lane produces zero Class A and zero
Class B findings. Class C findings each get a ruling, so what was set aside
stays auditable rather than dismissed — a ruling names the claim it answers and
the claims it does not, and is in force only while its signature verifies.
Ratified 2026-09-07 on the evidence of lane `5fb1b57`, where both reviewers
found sixteen defects and every one of them was in the gate rather than the
suite.

AM-17.10 (user-ratified 2026-09-09): what a killing test must be.
A mutant's `killing_tests` are the packet's claim that the suite would catch
that defect. The column asserted nothing checkable. Measured across the plan:
**38 of 65 mutants had neither killer covering the mutant's own requirement**,
only 5 had both, and 61 of 65 had a second killer whose index in the test list
was a function of the mutant's position — P1-M004 to P1-T04, P1-M005 to
P1-T05, cycling. The column was generated. F-55, F-59 and F-61 each re-anchored
one such mutant by hand without seeing they were samples of a pattern.
`verify_mutant_killing_tests` never caught it because it inspects only mutants
whose disposition is `killed`, and at stage 1a all 65 are `predeclared`.

Execution is not available to check this at 1a. AM-17.4 records that the
declared Phase 1 suite does not exist yet — 27 tests unwritten and 8
`#[ignore]`d — so a coverage matrix proving a test executes the mutated file
cannot be produced until Phase 1 is authorized. That proof belongs to HAQP-1b,
alongside the kill measurement itself.

What the packet CAN assert, and must, is that its killers are derived rather
than declared. For a mutant with requirement R and operator O:

1. **Candidates** are the tests the packet maps to R, in packet order. A test
   that does not defend R cannot witness a defect in R's defence.
2. **The primary killer** is the first candidate whose evidence kind is the one
   O is observed by, from the closed operator table in `haq.rs`: a
   `skipped-durable-transition` is observed by `recovery`, an
   `ordering-nondeterminism` by `replay`, a `stale-basis-acceptance` by
   `basis`, a `broadened-allow-list` by `negative`, and so on. Where R has
   several candidates of that kind — or none, and the whole candidate list
   stands in — the choice rotates by the mutant's position among those sharing
   R, so no one test carries a disproportionate share of the plan.
3. **The secondary killer** is the next remaining candidate, cyclically from
   the primary, whose evidence kind differs from the primary's, so the pair
   spans two ways of observing. If none differs, the next candidate stands and
   the pair observes one way twice — which no requirement in the current plan
   forces, and a test asserts that.

`verify_mutant_killing_tests` recomputes this for **every** mutant, whatever its
disposition, and refuses any packet whose column differs. The column is
therefore derived from the packet's own requirement map and operator table, and
cannot be authored freely again.

This does not make a declared kill a measured kill, and does not claim the named
test executes the mutated file. It closes the weaker gap, which was not that the
declaration was unproven but that it was arbitrary: tests named for mutants
whose requirement they do not defend.

Ratified 2026-09-09 on the evidence of lane `a53f6a4d`, where four of seven
findings were four instances of this one defect.

AM-17.11 (user-ratified 2026-09-11): the gate is frozen, and the
loop terminates on what a finding is ABOUT. Twenty-one lanes produced 131
verified defects at a mean of 6.3 per pass with no downward trend — 8, 11, 6,
8, 10, 9, 2, 9, 7, 5, 4, 4, 2, 5, 7, 9, 6, 14, 1, 4, 5. AM-17.9's termination
condition, zero Class A and zero Class B in one lane, has never been met and
the trend says grinding will not meet it.

The reason is visible in the last three lanes: their findings are almost
entirely against fixes made in the preceding two days. Lane `2bba9071` was four
for four against them. The suite under qualification stopped being the source
of findings several lanes ago; what generates them now is the qualifier's own
churn, and each lane's repairs open roughly as many seams as they close.

**The freeze.** From `9ebd9411`, a Class A or Class B finding is FIXED when it
concerns the artefacts under qualification — the packet, the suite, the seed
corpora, the production crates — and RECORDED as residual risk when it concerns
the qualifier's own implementation written during this campaign: `haq.rs` and
`scripts/haqp_*`. Recording means a ledger entry and a residual-risk row, not
silence, and a recorded finding still blocks a claim that the qualifier is
without defect. It does not block the flip, because the flip is a claim about
the SUITE.

**The termination rule, replacing AM-17.9's.** The loop ends when a lane's
Class A and Class B findings are all campaign churn — that is, when every one
of them names a coordinate whose line was last changed during this campaign.
`haq churn <file:line>` answers that from `git blame` against the campaign's
first lane, `0d8c32a` of 2026-09-05, so the classification is evidence rather
than the qualifier's judgement about its own work.

**What this does not do.** It does not declare the gate correct. A frozen gate
with recorded defects is exactly that: a measuring instrument whose known
imperfections are written down, used to measure something else. ADR-0020 §6
still asks the reviewer to attack the qualification as a whole, and it still
should — a finding against the gate is still a finding, still verified, still
recorded. What changes is that it no longer starts another round of edits to
the instrument, which is the loop that would not close.

**A08 at lane `3720d179` is the first finding this rule covers.** The ruling
matcher cannot decide whether two sentences describe one claim; four rounds
narrowed it and none closed it. It is recorded as RISK-004 rather than
narrowed a fifth time.

## Discovered gaps

DG17.1 (M17.1): ADR-0015 selects the constrained Markdown-compatible frontend
but does not bind a concrete parser package. The spike pins
`tree-sitter-md 0.5.3` with `tree-sitter 0.26.3` because it exposes block and
inline CSTs plus edited-tree incremental reparsing. Upstream explicitly warns
that its Markdown output retains known inaccuracies, and it has no lossless
native serializer; M17 therefore treats it as measurement evidence only and
keeps the declaration at Level 2. No production `liminal-cst` API depends on it.

DG17.2 (M17.4): ADR-0020 requires five fuzz campaigns before Phase 1 suite
ratification, while the implementation-plan defer list originally created
`fuzz/` only after the production `liminal-cst` crate landed. AM-17.2 permits
only conformance reference targets before authorization and preserves the
production-parser prohibition.

# M19 — Source maps, Human IR, explicit syntax, and derived graph (v4 §§10–17, 21, 121; Part XXII Phase 1)

**Status:** proposed Phase 1 work order — 2 weeks. Authored at the M17 gate; the
Phase 1 suite is unratified. The executor implements mechanically only after
explicit suite ratification; deviation = amendment or discovered gap, never silent.

## Scope

Build the deterministic source-preserving layer above M18: AtJSON-inspired
annotations/source maps, L1 Human IR, the eight-form v4 §17 explicit syntax, a
derived L2 Node/Relation graph at one Workspace Basis, and stable debug JSON v1.
Instantiate the existing canonical round-trip law across compact and explicit
forms. This activates the Phase 1 IR/schema portion of
`docs/implementation-plan.md` §4 item 12 only; it does not add CLI subcommands,
HTML, macros execution, transforms, plugins, AI, compiled Jurisdiction, sync, an
editor, or a persistent daemon.

## Pre-made decisions

- **D19.1 —** annotations and source maps are ephemeral views over one exact
  `SourceBasis`; raw offsets are never persisted without its content hash and
  never claim cross-revision identity.
- **D19.2 —** `SyntaxForm` is exactly v4 §17's literal, node construction,
  relation construction, attribute assignment, ordered block, reference,
  expression, and macro invocation. Compact syntax is sugar that lowers to these
  forms; macro invocation is represented but not executed in M19.
- **D19.3 —** HIR preserves authorial spelling, source ranges, symbolic defaults,
  unresolved references, and provenance. Resolution materializes defaults and
  local references into a separate derived graph; it never mutates HIR.
- **D19.4 —** external-file source retains Jurisdiction. The L2 graph is marked
  derived, carries the exact Workspace Basis and source provenance, and is never
  selected as a governing Holder.
- **D19.5 —** stable debug JSON v1 is the only Phase 1 graph interchange. It is
  inspectable and deterministic but explicitly non-final and non-performance-
  critical; unknown or missing fields fail closed.
- **D19.6 —** canonical semantic IDs use UUIDv5 with `Uuid::NAMESPACE_URL` over
  `b"liminal:phase1:derived:v1\0" || subject_tag || 0x00 || holder_source_uuid ||
  0x00 || form_kebab || 0x00 || path_len_be_u32 || child_index_be_u32*`.
  `subject_tag` is exactly `b"node"`, `b"relation:explicit"`,
  `b"relation:contains"`, or `b"relation:reference"`; the path is the preorder
  root/child-index path. Source offsets and content hash do not enter the ID. A
  unique explicit ID instead uses UUIDv5 over
  `b"liminal:phase1:explicit:v1\0" || holder_source_uuid || 0x00 || id_utf8`.
  The resulting continuity is Anchored for the derived recipe and Explicit for
  the accepted explicit recipe, never Managed.
- **D19.7 —** `Phase1Document::PartialEq` compares the normalized semantic
  Node/Relation projection and its Workspace Basis. It deliberately excludes
  diagnostics, source hashes, provenance coordinates, and source-map byte ranges,
  which may change when canonical spelling changes without semantic loss.
- **D19.8 —** the only Phase 1 semantic defaults are empty attributes, an empty
  fence `info` string, and empty macro arguments. Canonical explicit emission
  writes all three; no domain/schema default is invented before its owning phase.

JSON bytes are UTF-8, one pretty-printed object, two-space indentation, LF only,
and one trailing LF. Struct field order above is canonical; every map is a
`BTreeMap`; `nodes`, `relations`, and `provenance` sort by subject ID;
`schema_version` must equal `1`; duplicate IDs, dangling endpoints, unknown or
missing fields, non-derived nodes, missing Node/Relation provenance, and
Basis/source-hash mismatch are errors. Strict decoding deserializes into
`DebugGraphV1`, serializes that value to a canonical `serde_json::Value`, then
recursively requires identical object-key sets, array lengths, and JSON kinds
between input and canonical value. The first difference returns
`DebugJsonError::Shape { path }`; embedded existing types therefore reject
unknown or missing fields too.

`Phase1Document`'s explicit
`PartialEq` implementation follows D19.7 by comparing the Workspace Basis and a
semantic projection of sorted Nodes/Relations; source hashes, ranges,
diagnostics, and provenance coordinates are excluded. `MarkdownFormatter`
implements the existing
`Formatter<Doc = Phase1Document, Error = Phase1FormatError>` seam for both the

`CompactMarkdown` lowers M18 typed nodes directly. `ExplicitV1` reparses the

tokens and recovery ranges in the same source map. Canonical `emit` always writes
ExplicitV1. `parse(source)` constructs `SourceBasis { source: self.source,
content_hash: ContentHash::of(source.as_bytes()) }`, loads `Utf8HolderView`, runs
M18 `parse`, calls `lower` with `self.dialect`, and resolves only against
`self.basis`. The formatter appends HIR diagnostics in their defined source
order, followed by resolve
diagnostics sorted by `(subject, code, message)`; formatting errors remain fatal
and never appear in that vector.

The explicit v4 §17 grammar is:

```ebnf
document   = spacing, { form, spacing } ;
form       = literal | node | relation | attribute | ordered
           | reference | expression | macro ;
literal    = "literal", space1, string, ";" ;
node       = "node", space1, ident, [ attributes ], block ;
relation   = "relation", space1, reference_value, spacing, "-[", ident,
             "]->", spacing, reference_value, [ attributes ], ";" ;
attribute  = "attribute", space1, ident, spacing, "=", spacing, value, ";" ;
ordered    = "ordered", spacing, block ;
reference  = "reference", space1, reference_value, ";" ;
expression = "expression", space1, string, ";" ;
macro      = "macro", space1, ident, "(", [ values ], ")", ";" ;
block      = "{", spacing, { form, spacing }, "}" ;
attributes = "(", [ assignment, { ",", spacing, assignment } ], ")" ;
assignment = ident, spacing, "=", spacing, value ;
values     = value, { ",", spacing, value } ;
value      = string | integer | "true" | "false" | "null" | reference_value ;
reference_value = "@", ident ;
ident      = (ALPHA | "_"), { ALPHA | DIGIT | "_" | "." | ":" | "-" } ;
string     = JSON_STRING ;
integer    = [ "-" ], DIGIT, { DIGIT } ;
spacing    = { " " | "\t" | "\r" | "\n" | comment } ;
space1     = ( " " | "\t" | "\r" | "\n" ), spacing ;
comment    = "//", { codepoint - "\r" - "\n" }, [ "\r" ], [ "\n" ] ;
```

Keywords are lowercase ASCII and reserved; identifiers are case-sensitive;
strings use JSON escapes and Unicode scalar values; integer overflow is a typed
HIR diagnostic. Nesting uses M18's `MAX_NESTING`. Recovery consumes through the
next `;` at current brace depth or the current block's `}`, whichever comes first,
while retaining every consumed CST token under the originating error annotation.
The productions map field-for-field: `literal` supplies `Literal.value`; `node`
supplies `NodeConstruction.name`, its parenthesized assignments supply
`attributes`, and its block supplies ordered `children`; `relation` supplies
`RelationConstruction.source`, `.kind`, and `.target` plus its parenthesized
`attributes`; `attribute` supplies `AttributeAssignment.name` and `.value`, with
`owner` set to the nearest enclosing Node or Relation's `HirId` and a top-level
assignment retained with `owner = None` plus `AttributeWithoutOwner`; `ordered`
supplies ordered `children`;
`reference` supplies `Reference.target`; `expression` supplies
`Expression.source`; and `macro` supplies `MacroInvocation.name` and ordered
`.arguments`. Only Node and Relation items may have nonempty `attributes`; only
Node and OrderedBlock items may have nonempty `children`. `SyntaxForm` is the
one-to-one tag obtained from `HirItemKind`, never independently stored.

Compact lowering maps the M18 document's block children to HIR roots exactly:

| M18 CST | HIR projection |
|---|---|
| ATX heading | `NodeConstruction { name: "heading" }`; integer `level`; inline children |
| paragraph | `NodeConstruction { name: "paragraph" }`; inline children |
| ordered/unordered list | `NodeConstruction` named `ordered-list`/`unordered-list`; ordered `list-item` children; ordered items carry integer `ordinal` |
| block quote | `NodeConstruction { name: "block-quote" }`; one `paragraph` child per quote line |
| fenced code | `NodeConstruction { name: "code-block" }`; string `info`; one exact-body `Literal` child |
| plain text | `Literal { value }`, coalescing adjacent text tokens |
| emphasis/strong/inline code | `NodeConstruction` named `emphasis`/`strong`/`inline-code`; inline children, with inline-code bytes in one `Literal` |
| link | `NodeConstruction { name: "link" }`; string `destination`; label inline children |
| explicit ID | string `id` attribute on its enclosing block |
| `Opaque` | `NodeConstruction { name: "opaque" }`; string `class` equal to `extension`, `html`, or `unsupported`; one exact-byte `Literal` |
| `Error` | `NodeConstruction { name: "error" }`; one exact-byte `Literal` plus `MalformedSyntax` diagnostic |

Blank lines and nonsemantic delimiters create annotations but no HIR item. All
table attributes occupy the owning item's `attributes` map. Parenthesized
explicit attributes populate `attributes`; an
`AttributeAssignment` contributes to its owner's effective attributes during
resolution without mutating HIR. On a repeated key, the first source-order value
wins and the later assignment produces `MalformedSyntax`.

The HIR-to-graph projection is field-exact:

1. Create one synthetic document `Node`, then one `Node` for each `Literal`,
   `NodeConstruction`, `OrderedBlock`, `Expression`, and `MacroInvocation` item.
   Their kind names are respectively `literal`, the construction's `name`,
   `ordered-block`, `expression`, and `macro-invocation`.
2. Set each Node's `payload` to
   `PayloadRef::Text(serde_json::to_string(&DerivedPayloadV1 {
   schema_version: 1, kind, attributes })?)`, `revision` to `RevisionId(0)`, and
   flags to `NodeFlags::DERIVED`. Add `HAS_DURABLE_ID` only for a unique string
   `id` attribute.
3. Emit one `contains` Relation from every document, NodeConstruction, or
   OrderedBlock parent to each Node-producing child. Its payload is the child's
   zero-based decimal position, preserving declared order.
4. Emit `RelationConstruction` directly from its resolved `source` to
   `Target::Node(target)`, using its `kind`; emit `Reference` from the nearest
   Node-producing ancestor, or the document Node at top level, to its resolved
   target with kind `reference`. `AttributeAssignment` emits no graph subject;
   it changes only its owner's effective payload attributes.
5. Every Relation uses `revision = RevisionId(0)`,
   `RelationFlags::default()`, and `requires = None`. Its payload is
   `PayloadRef::Text` of `DerivedPayloadV1` for an explicit/reference Relation
   and the decimal child position for `contains`.

`KindId` is the first four bytes, big-endian, of
`BLAKE3(b"liminal:phase1:kind:v1\0" || declared_name_utf8)`, bitwise-OR
`0x8000_0000`. Resolution records the first name for every result and returns
`ResolveError::KindCollision` if a distinct, case-sensitive declared name
collides. No case folding or punctuation normalization occurs. The symbol table is
built from unique string `id` attributes over the whole document. A duplicate
produces `DuplicateExplicitId`, neither duplicate is accepted into the symbol
table, and both Nodes fall back to D19.6 Anchored IDs. Every unresolved target
produces `UnresolvedReference` and no Relation; it is never redirected.
For D19.6, `form_kebab` is the `SyntaxForm` tag for an authored subject,
`node-construction` for the synthetic document Node, `contains` for a generated
containment Relation, and `reference` for a generated reference Relation. The
synthetic document provenance spans the whole source; Node/explicit/reference
provenance uses that HIR item's range; containment provenance uses the child
item's range. Unique explicit-ID Nodes have `IdentityGrade::Explicit`; every
other Node and every Relation has `IdentityGrade::Anchored`.
Every public item, field, function, method, and enum variant specified above
receives a doc comment citing v4 §§10–17, §21, or §121 as applicable.

## Algorithms

1. Walk the M18 typed CST in source order and create annotations for each token,
   error region, attribute, reference, and recognized form. Allocate dense
   `HirId`s preorder from zero; validate the complete SourceMap before returning.
2. Lower compact Markdown sugar and explicit syntax into the same eight-form HIR
   using the production mapping above.
   Explicit syntax accepts only `literal`, `node`, `relation`, `attribute`,
   `ordered`, `reference`, `expression`, and `macro`; unknown forms become HIR
   diagnostics while their M18 CST bytes remain lossless. Integer overflow,
   malformed syntax, and ownerless
   attributes likewise produce typed, nonfatal HIR diagnostics; invalid source
   maps and dangling resolved HIR IDs are fatal `HirError`s.
3. Resolve HIR at one caller-supplied `WorkspaceBasis`. Materialize symbolic
   D19.8 defaults and local references; retain unresolved references as
   `ResolveDiagnostic`s;
   never perform I/O inside lowering. Derive IDs by D19.6, mark every Node
   `NodeFlags::DERIVED`, attach Anchored provenance to every Node and Relation,
   sort by ID, and reject dangling Relations. Return those nonfatal diagnostics
   beside the graph in `ResolvedGraph`; Basis mismatch and dangling derived
   relations remain fatal `ResolveError`s.
4. Convert `DerivedGraph` to `DebugGraphV1`, validate every invariant, serialize
   with the fixed v1 framing, deserialize with `deny_unknown_fields`, and require
   structural equality. No JSON bytes are used as a governing store snapshot.
5. Canonical emission walks normalized HIR: attributes sort lexicographically,
   children retain declared order, literals use JSON string escaping, and every
   implicit default is written explicitly. Parsing compact or explicit input,
   emitting canonical explicit form, and parsing again must produce an equal
   `Phase1Document` under D19.7.
6. Fill the existing law test with compact/explicit pairs covering all eight forms,
   derived-graph provenance, malformed-but-retained regions, and deterministic
   repetition. Invoke
   `laws::check_canonical_round_trip` unchanged, then exercise strict v1 rejection
   in the same existing test. The positive JSON case must satisfy
   `serialize(deserialize(serialize(value))) == serialize(value)` byte-for-byte.
   Negative cases must reject malformed JSON, a wrong version, duplicate IDs,
   dangling endpoints, a non-derived node, missing Node provenance, missing
   Relation provenance, Basis/source-hash mismatch, and an unknown or missing
   field. Do not duplicate or weaken the generic law and do not create another
   test.

# M13 — Constitutional kernel and governed examples (v4 §§1–8, §19, Part XXII Phase 0)

**Status:** work order — 1.5 weeks. Authored at the M12 gate. The executor
implements mechanically; deviation = amendment or discovered gap, never silent.

## Scope

Turn `spec/kernel.md` from an index into a self-contained constitutional chapter,
publish the interpretive Contract and Workspace Basis rules, publish the tiered
vocabulary ceiling, and encode six governed representation examples. This order
does not build a parser, CST, compiled Jurisdiction plan, UI, or new semantic
primitive (`docs/implementation-plan.md` §4 items 1, 3, 10, 11, 12).

## Spec inputs

v4 §§1–8, §19, §43–48, §118A, Part XXII Phase 0; R4 §§1–3, §8, §10;
`docs/adr/0009-cap-identity-promises-at-phase-minus-1-evidence.md`;
`docs/adr/0013-phase-0-go-no-go-after-falsification-laboratory.md`; M03, M06,
M07, and M12.

## Frozen surfaces

Node and Relation are the only semantic primitives. Existing public Contract,
Holder, Basis, and identity-grade shapes remain reference semantics. Canonical
`spec/v4/**` files are immutable. Example IDs, test names, and fixture version 1
below are frozen once this order lands. No `FacetId` or third subject may appear.

## Pre-made decisions

- **D13.1 —** `spec/kernel.md` becomes normative, self-contained prose but cites
  canonical v4/R4 and accepted RFCs for authority; it does not copy Rust source.
- **D13.2 —** six examples use only Node and Relation with the exact topology
  table below: prose, code block, table, image reference, audio interval, and
  synchronized external value. A domain label alone proves nothing.
- **D13.3 —** every Node and Relation names expected profile, Holder, and minimum
  identity grade; `Ungoverned` and implicit identity are invalid fixture states.
- **D13.4 —** user-facing vocabulary is domain-native. Jurisdiction, Holder,
  Overlay, and Promotion are an explanation ceiling, not routine UI text.
- **D13.5 —** external-file defaults to Anchored; graph-native and
  EXTERNAL_VALUE default to Managed, exactly as ADR-0009 and AM-12.3 freeze.

```toml
[[example.relation]]
role = "contains" # fixture semantic, persisted in payload
kind = "COMMENT" # Phase -1 toy's graph-native Relation dispatch key

to = "body"
payload = "contains"
expected_profile = "graph-native"
expected_holder = "graph"
minimum_identity = "managed"
```

Node `role` is fixture-only vocabulary used by the topology oracle; it is not
written to graph state. Relation `role` is persisted as its canonical text payload
while live `Relation.kind` remains `COMMENT`, the Phase -1 toy's only graph-native
Relation dispatch key. This preserves semantic distinctions without inventing
future domain `KindId` values. Node `payload` is UTF-8 text or canonical JSON text
where the table below names fields. Each example has non-empty, unique `id`; exact
nodes and relations required below; live Node kinds restricted to `FILE`,
`PARAGRAPH`, and `EXTERNAL_VALUE`; relation endpoints naming aliases in the same
example; and per-subject expected profile, concrete Holder, and grade.
`minimum_identity` uses `IdentityGrade` kebab-case spelling. Domain is closed to
the six values for v1.

| Domain | Exact node roles and live kinds | Exact Relation roles (`kind=COMMENT`) and payload constraints |
|---|---|---|
| prose | `document:FILE`, `paragraph:PARAGRAPH` | `contains(document, paragraph)`; paragraph payload non-empty |
| code | `document:FILE`, `code-block:PARAGRAPH` | `contains(document, code-block)`; canonical payload object has non-empty `text` and `language = "rust"` |
| table | `document:FILE`, `table:PARAGRAPH`, two `row:PARAGRAPH`, four `cell:PARAGRAPH` | document contains table; table contains both rows; each row contains two cells; `next(row-1,row-2)`; every cell payload non-empty |
| image | `document:FILE`, `image-reference:PARAGRAPH` | `embeds(document, image-reference)`; canonical payload object has `sha256` as 64 lowercase hex plus non-empty `mime` and `alt` |
| audio-interval | `document:FILE`, `audio-interval:PARAGRAPH` | `contains(document, audio-interval)`; canonical payload object has resource `sha256` plus unsigned `start_ms < end_ms` |
| external-value | `external-source:EXTERNAL_VALUE`, `value:EXTERNAL_VALUE` | `materializes(external-source, value)`; canonical payloads carry non-empty source ID, revision token, observation timestamp, and value |

Validator compares aliases, kinds, relation triples, multiplicities, and listed
payload predicates exactly, including equality of Relation role and persisted
payload text. For the first five examples, every FILE/PARAGRAPH is
external-file/its declared file/Anchored and every Relation is
graph-native/graph/Managed. Both external-value Nodes and its Relation are
graph-native/graph/Managed. Six copies of one topology with different labels fail.

## Algorithms

1. Expand `spec/kernel.md` into normative sections for constitution, kernel,
   Jurisdiction Contract, Holder resolution, Workspace Basis/Perspectives,
   profile selection, identity, representation, and vocabulary. Every MUST maps
   to a live type, accepted ADR/RFC, or conformance assertion.
2. Load fixture v1 with `serde(deny_unknown_fields)` structs local to Phase 0
   conformance. Reject duplicate IDs/aliases, missing relation endpoints,
   unknown profiles/grades/domains, topology/multiplicity drift, invalid payload
   predicates, and non-concrete Holders.
3. Materialize exact live kinds/payloads/relations through existing graph
   transactions and profile dispatch. Enumerate subjects through
   `Checker::subjects`; assert every subject resolves to its per-subject expected
   profile and Holder and meets its declared minimum grade.
4. Compare each materialized example against the exact topology table, including
   decoded Relation role payloads, then
   assert state contains only Nodes and Relations. Search production Rust for
   prohibited facet identifier spellings using split needles so the prohibition
   test never allow-lists itself.

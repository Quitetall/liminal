## Data schemas

`paragraph.rs`:

```rust
pub struct Block { pub text: String, pub id: Option<String>, pub range: SourceRange }
pub fn parse(input: &str) -> Vec<Block>   // TOTAL — never errors (Law 3B)
```

Grammar rules (exhaustive):
- A **block** is a maximal run of non-blank lines; a blank line is empty or
  whitespace-only; blocks are separated by ≥1 blank lines; leading/trailing blank
  lines produce no blocks.
- **ID marker:** if the block's final line ends with `{#` + id + `}` where id
  matches `[A-Za-z0-9_-]+` (nonempty), optionally preceded by spaces/tabs:
  `id = Some(id)`; `text` = lines joined `\n` with the marker (and preceding
  spaces/tabs) stripped from the last line, then that line's trailing whitespace
  stripped.
- **Malformed stays literal:** unclosed `{#`, empty id, invalid chars, or marker
  not at end-of-block → `id = None`, text unchanged. Only the LAST suffix is a
  marker: `foo {#a} {#b}` → id `b`, text `foo {#a}`.
- `range` = byte span of the block in the input (inclusive/exclusive), including
  marker bytes, excluding surrounding blank lines.

Ingestion per `[[setup.file]]` (one commit each, in the daemon runner; replaces
M02's `setup.graph` bail):
1. `CreateNode` FILE node (payload `None`); raw bytes →
   `put_aux(SYS_BLOB, "file/<path>", <json string of bytes>)`.
2. Per parsed block i: `CreateNode` PARAGRAPH node — payload `Text(block.text)`,
   flags `HAS_DURABLE_ID` iff id present.
3. `InsertChild { parent: file, child: para, index: i }` in parse order.
4. Per id: `put_aux(JUR_ALIAS, id, {"node","entity"})` (D03.3).

Per `[[setup.graph]]` `kind = "comment-relation"`: `CreateNode` COMMENT node
(payload `Text(body)`) + `AddRelation { source: comment, target:
Node(alias→node), kind: COMMENT, requires: Some(IdentityRequirement { minimum:
<requires_grade> }) }` (AM-3.1).

## Algorithms

### A. Contract literals (returned verbatim by `contract_for`)

`ExternalFileProfile` — FILE/PARAGRAPH nodes (path from the owning file's blob
key):

```rust
JurisdictionContract {
    scope: SubjectSelector::Exact(subject),
    resolution: HolderResolution {
        candidates:      vec![Holder::File { path }],
        read_precedence: vec![Holder::File { path }],
        fallback:        None,                    // unavailable → Overlay, never a block (Law 3B)
        merge_runtime:   None,                    // §7.11's "Text/Git" is external, not a Federated runtime
    },
    mutation: MutationPolicy {
        write_route: Holder::File { path },
        foreign_edits: ForeignEditPolicy::Accept, // v4 §8.5 step 4
        repair_authorization: RepairAuthorization::Automatic,
        safety: SafetyRequirement::StructuralDisjointness, // v4 §7.7
    },
    continuity: ContinuityPolicy {
        required_identity: IdentityGrade::Anchored,        // FLOOR (D03.5)
        on_dangling: DanglingPolicy::PreserveAndSurface,   // v4 §7.7 final bullet
    },
    lifecycle: LifecyclePolicy {
        surface_after: Duration::from_secs(0),             // D03.6
        escalate_after: Duration::from_secs(3600),
        declared_transient: true,                          // offline drafts awaiting sync (R4 §2.3)
    },
}
```

`GraphNativeProfile` — COMMENT nodes and ALL Relations: same shape with
`candidates/read_precedence = vec![Holder::Graph]`, `write_route: Holder::Graph`,
`foreign_edits: Review` (v4 §8.2: byte equality is not the merge protocol),
`required_identity: Managed` (v4 §7.6/§7.11), `declared_transient: false`.

### B. `grade_of(subject)` (new fn in checker.rs, used by Q4)

| Subject | Grade |
|---|---|
| PARAGRAPH node with `HAS_DURABLE_ID` | Explicit |
| PARAGRAPH node without | Anchored |
| FILE node | Anchored |
| COMMENT node | Managed |
| any node with `Object(_)` payload | ContentAddressed (overrides; unused at M3) |
| any Relation | Managed |

`Inferred` first appears with M4/M7 heuristic re-ingestion; not producible at M3.

### C. Checker Q1–Q8

- **Q1 `resolve_holder`:** contract = dispatch + `contract_for`; if
  `basis.perspective` is `ClientScoped{client}` AND the owning file's
  `basis.components[Path(p)]` is `BufferGeneration{client: c == client, buffer, ..}`
  → `Holder::Buffer{client, buffer}`; else `read_precedence[0]`.
- **Q2 `write_route`:** `contract.mutation.write_route` verbatim (buffer capture
  is not routing).
- **Q3:** `contract.resolution.merge_runtime.clone()` (always None in Phase -1).
- **Q4 `identity_satisfies_relations`:** for each Relation targeting the node with
  `requires = Some(req)`: `!grade_of(node).satisfies(req.minimum)` → JUR041.
  Alias claimed by ≥2 live blocks → JUR042.
- **Q5 `unresolved_overlays`:** scan `JUR_OVERLAY`, keep
  `Active|RepairProposed|Contested`, filter by subject, sorted. (Empty before M5 —
  which is what soundness needs.)
- **Q6:** already implemented.
- **Q7 `authorize`:** per step, consult ONLY `step.subject`'s own contract (that
  IS Law 3F); `ReviewRequired` → refusal JUR051.
- **Q8 `evaluate_repair`:** conjunction collecting reasons: (a) basis current
  (plan.basis.transaction vs head) else JUR053; (b) every prestate matches now
  else JUR053; (c) Q7 refusals empty else JUR051; (d) retargeting steps pass Q4 at
  the new target else JUR041; (e) `profile.safety_check` errors map to JUR052;
  (f) `inverse.is_some()` else JUR052. All hold → AutoApply, else
  NeedsReview(reasons). **No Reject exists.** M3 ships a trivial safety_check
  (steps touch pairwise-distinct subjects → Ok); M4 replaces it.
- **`check_workspace`:** Q4 over every node with incoming required Relations +
  JUR050 per unresolved overlay + JUR042 for ambiguous aliases; findings sorted by
  `(code, subject)`.

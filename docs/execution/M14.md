## Scope

Publish executable normative text for mutation-local repair, unified
RepairPlan/Promotion, ILRP recovery, Overlay aging, Reconciliation Queue
surfacing, and all four Basis Perspectives. Align recovery-fixture documentation
with derived crash traces. This order changes no live semantics and builds no

## Spec inputs

## Frozen surfaces

`RepairPlan`, `RepairDecision`, `SafetyRequirement`, `IntentState`, five ILRP
fault-point names, `PrestateMatch`, `OverlayState`, `ReconciliationItem`,
`BasisPerspective`, `WorkspaceBasis`, and `BasisComponent` shapes. Existing crash
scenario IDs and terminal states are frozen. No `Reject` repair decision and no
silent Overlay deletion may be introduced.

## Pre-made decisions

- **D14.1 —** authorization remains conjunctive and mutation-local; no subject's
  Contract confers write authority over another subject.
- **D14.2 —** Promotion is display vocabulary for an accepted RepairPlan, never a
  second state machine.
- **D14.3 —** automatic application requires authorization, exact prestate,
  identity/invariant preservation, domain safety, idempotency, and recorded undo.
- **D14.4 —** recovery derives cases from baseline hit traces. Hand-listed crash
  points are explanatory only and cannot define coverage.
- **D14.5 —** Overlay debt leaves active state only by accepted repair, explicit
  discard, or searchable archive. Aging changes visibility, never durability.
- **D14.6 —** requester-less or ambiguous computations resolve DurableOnly;
  client-scoped Bases can select components from only the requesting client.

## Data schemas

No new runtime schema. Publish normative tables in `spec/kernel.md` for:

- repair auto-apply conjunction and exact evidence fields;
- ILRP state transition × prestate classification × permitted action;
- five durable boundary names and required recovery terminal set;
- Overlay state transition × queue visibility × allowed actor;
- BasisPerspective × eligible component classes × ambiguity result.

`conformance/fixtures/ilrp-crash-matrix/README.md` remains descriptive; executable
case enumeration stays derived by `ToyRun::baseline` and `ToyRun::crash_matrix`.

## Algorithms

1. Generate a live shape appendix in the test from serde JSON examples and enum
   debug names; compare every normative table row to the live reference types.
2. For every runnable crash scenario, require non-empty baseline hits, one case
   per `(point, occurrence)`, a non-empty first recovery terminal set, terminal
   membership in Committed/NeedsReview/Aborted, equal first/second recovery
   digest, and no unregistered durable boundary.
3. Execute canonical safe, unsafe-unique, two-step DAG, third-state recovery,
   offline Overlay, and two-dirty-buffer scenarios as normative witnesses.
4. Validate `spec/kernel.md` contains a unique anchor for every frozen table row;
   duplicated or missing normative identifiers fail rather than warn.

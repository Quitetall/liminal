# Phase 0 threat model

**Scope:** graph store, filesystem Holders, clients and buffers, resolver
observations, repair execution, plugins and processes, corpus handling, and
supply chain. Phase 0 is pre-release; controls are claimed only where named
verification exists. Unsupported mitigations remain residual risk.

## Security invariants

- Capture never becomes silent loss; unsafe state remains reviewable.
- Durable recovery never guesses past a prestate mismatch.
- One client never reads another client's dirty buffer through a Basis.
- Effects and external observations enter pure computation through accepted
  transactions and explicit provenance.
- Locked acceptance data is verifier-only and never a profile-tuning input.
- Store corruption, dependency-policy failure, and malformed inputs fail closed.

## Review and change rule

Threat IDs are never reused. New threats append rows. A control without
executable or procedural verification must be described as residual risk, not a
mitigation. Phase 1 review must add parser/CST, debug interchange, Salsa or
replacement engine, HTML rendering, and developer-tool boundaries before code
crosses them.
